# SOLID in JavaScript and TypeScript

- Review responsibility across modules, functions, closures, objects, classes, components, and services.
- TypeScript structural types can satisfy contracts accidentally; document semantic guarantees and test implementations against consumer expectations.
- Use functions, higher-order functions, discriminated unions, middleware, and modules where they are clearer than interfaces and classes.
- Runtime validation is separate from TypeScript typing and belongs at trust boundaries.
- LSP includes promise behavior, rejection/error shape, cancellation, ordering, side effects, and event-listener lifecycle.
- Avoid interface proliferation and DI containers when module imports or explicit factory parameters provide a clear stable boundary.
