# Compatibility and Evidence

Classify each change as additive-compatible, conditionally compatible, or breaking against the approved policy and every supported consumer. Schema acceptance alone does not prove semantic compatibility when defaults, errors, ordering, side effects, units, meaning, or timing commitments change.

A trustworthy verification records the exact provider and consumer revisions, contract version/hash, verifier/tool version, environment or registry/broker state, fixtures, result, and retention location. Pending or stale consumer verification is visible risk, not a pass.

Use `Contract-Passed` only when all required supported consumers/providers and compatibility checks pass. Use `Contract-Failed` for an observed incompatibility. Use `Contract-Blocked` when the authoritative contract, consumer inventory, environment, ownership, or trustworthy execution is unavailable.
