# Kafka Reference

Reason about brokers, topics, partitions, leaders/replicas, ISR, consumer groups, offsets, retention, compaction, rebalancing, and replication together. Partitioning determines parallelism and per-key ordering; consumer count above partition count does not increase throughput. Configure producer acknowledgements, batching, compression, retries, and idempotence with the required durability and latency trade-offs. Monitor under-replicated partitions, broker health, publish/consume latency, lag, message age, and storage growth.
